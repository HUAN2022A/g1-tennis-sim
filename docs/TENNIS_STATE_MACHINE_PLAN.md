# #8 高层状态机方案：无学习版网球击球闭环

撰写日期：2026-09-04
前置依据：`docs/TENNIS_REPLICATION_HANDOFF.md`（现状）、`docs/LATENT_PAPER_NOTES.md`（LATENT 论文调研）
关联验证：#6 命中测试已证明 50g 拍 + 14-15 m/s 挥速下拍-球碰撞稳定无穿模（`scripts/tennis_hit_test.py`）

## 1. 目标与范围

**目标**：构建"感知球状态 → 决策 → 触发挥拍 → 击中球"的闭环，即交接文档第 10 节第 8 条"基于球状态选择已有动作片段并控制触发时机"。

**范围界定（基于 LATENT 调研的两步走）**：

- **本方案 = 第一步"无学习版"**：规则状态机 + 现有 ONNX 跟踪策略，验证闭环可行性。只追求"命中"，不追求"回球到指定落点"。
- **第二步（RL 微调，另立方案）**：LATENT 式训练（腕部修正接口 + 域随机化 + PPO），需 8 GPU 级训练资源，不在本方案内。LATENT 消融已证明：无腕部修正时落点精度大幅下降——这是无学习版的天花板，属预期而非缺陷。

**明确不做（本方案内）**：视觉感知（球状态由仿真直接给出，加噪声模拟）、语言指令、动作生成。

## 3. 系统设计

```text
                    ┌────────────────────────────────┐
                    │  球发射器（脚本化，带随机化）    │
                    │  位置/速度采样 + 球物理 DR       │
                    └──────────────┬─────────────────┘
                                   ▼
┌──────────────────────────────────────────────────────────────┐
│ 球观测模块                                                    │
│  输入：仿真真值球位置（+均匀噪声 + 帧 dropout + 延迟）         │
│  速度：4 帧滑窗平均（LATENT 4.2 节，位置差分对噪声极敏感）      │
└──────────────┬───────────────────────────────────────────────┘
               ▼
┌──────────────────────────────────────────────────────────────┐
│ 轨迹预测模块                                                  │
│  弹道模型：重力 + 空气阻力 f = −k·m·v·|v|（k∈[0.01,0.04]）     │
│  + 地面反弹（restitution 0.71-0.79）                          │
│  输出：预测到达击球高度平面的 位置/时刻                         │
└──────────────┬───────────────────────────────────────────────┘
               ▼
┌──────────────────────────────────────────────────────────────┐│ 高层状态机（50Hz）                                           │
│  IDLE ──球发射──▶ TRACK ──预测收敛──▶ ARM ──时机到──▶ SWING   │
│    ▲                                   │                      │
│    └───────── 片段结束/球落地 ◀─────────┘ (→ RECOVER → IDLE)  │
│  决策内容：                                                   │
│   1. 挥拍触发时刻 t_trigger = t_arrive − T_lead                │
│      （T_lead = 片段起点到拍面峰值帧的时长，离线标定）          │
│   2. 片段选择（V2）：根据预测 interception 点在身体左/右侧      │
│      选正手/反手片段；V0/V1 固定 Random_001                    │
└──────────────┬───────────────────────────────────────────────┘
               ▼
     现有低层：ONNX 跟踪策略 → 29 电机目标 → PD → MuJoCo
```

### 3.1 关键设计点

**a) 击球时机的确定（核心问题）**

挥拍片段不是瞬时的——从触发到拍面达到峰值速度有固定提前量。方法：

1. 离线：用 `tennis_hit_test.py` Phase A 对每个片段标定 `T_lead`（**挥拍 onset 帧到 `site_vel` 峰值帧的时长**）和峰值帧拍面位置 `P_swing`（拍面经过点）。onset 用 site 速度阈值判据自动确定（速度突破阈值且即将进入挥拍加速的帧），不硬编码帧号——同一判据可复用到 V2 的其他片段。
   - **2026-09-04 修订**：最初版本把 T_lead 定义为"片段第 0 帧到峰值帧"，实测 Random_001 该值为 3.30s——其中前 1.1s 是静止准备姿势、再 2s 是慢速预摆，真正的挥拍加速只有 0.34s。3.3s 提前量要求发射弹道 apex ≈ 16m，物理荒谬。修订后从 onset 帧开始跟踪，T_lead ≈ 0.9-1.3s，对应 apex 2.3-4m 的挑高球。附带发现：片段的"准备段"在 V3（移动击球）可能有用——走位期间可以持有该段。
2. 在线：预测的球到达时刻 `t_arrive` 满足 `t_trigger = t_arrive − T_lead` 即触发；同时要求预测拦截点与 `P_swing` 的偏差在容差内（如 < 0.15 m），否则判 MISS 不挥拍（避免无意义挥动）。

这与 #6 的区别：#6 是"已知拍面轨迹，把球放到拍面经过点"（逆向）；本方案是"已知来球，决定何时挥拍"（正向）。#6 的确定性回放保证了片段的拍面轨迹可复现，是本方案可行的前提。

**b) 发球器的随机化（为后续 RL 和鲁棒性预研）**

按 LATENT Table 2 只随机化球相关项：质量 ×U(0.95,1.05)、弹性 U(0.71,0.79)、切向阻尼 U(0.4,0.7)、空气阻力 k U(0.01,0.04)。发射条件（位置/速度）在"能被当前片段命中"的可行域内采样——可行域从离线拍面轨迹推出（峰值帧附近 ±N 帧的拍面位置及其可达球速范围）。

**c) 观测噪声（V1 引入）**

球位置加均匀噪声（如 σ=5mm 起步）+ 帧级 dropout（如 p=0.05）+ 1-2 帧延迟。V0 先用无噪声真值打通闭环，再逐步加噪观察退化曲线——这同时是"第二步 RL 训练"的观测接口预研。

**d) 状态切换的连续性**

`play_track.py` 已实现 walk↔track 模式切换（含 reset），状态机复用该机制。V1 的 walk-to-position 需要处理：walk 结束姿态 → 跟踪片段初始姿态的差异（片段自带初始 reset，接受瞬间的 reset 跳变；V1 先在仿真容忍）。

## 4. 分阶段里程碑

| 版本 | 内容 | 验收标准 |
|---|---|---|
| **V0 站桩命中** | 机器人固定在挥拍 onset 姿态；单球发射（无噪声真值观测）；预测模块 + IDLE/TRACK/SWING 状态机 + 时机触发 | 固定发射模式下命中率 ≥ 80%（20 球） |
| **V1 鲁棒命中** | 发射条件随机化 + 球物理 DR + 观测噪声/延迟；MISS 判定与不挥拍逻辑 | 随机可行域内命中率 ≥ 50%，且记录命中/失误原因分类 |
| **V2 片段选择** | 根据拦截点左右侧选择正/反手片段（需补充反手片段并标定）；多球连续（间隔 ≥ 模拟 LATENT 的 2s） | 正反手各 ≥ 20 球，混合命中率 ≥ 40% |
| **V3 移动击球** | walk policy 导航到拦截点附近 → 切换挥拍片段 | 移动后命中率不再大幅劣于站桩（如 < 10pp 衰减） |

每版产出：可复现脚本 + `logs/` 评估日志 + 简报。V0/V1 预计单会话各一版；V2 依赖反手数据（p1 里是否有反手片段待确认——四条轨迹均为 Random 命名，语义未知，需先人工看视频/叠影标注）。

## 5. 代码组织（初步）

- `utils/ball_obs.py`：球观测（噪声 + 4 帧滑窗速度）——独立模块，V0 可跳过直接真值
- `utils/ball_predict.py`：弹道预测（阻力 + 反弹）
- `scripts/tennis_serve.py`（或并入现有）：发射器 + 随机化
- `deploy/tennis_brain.py`（新宿主，或并入 `play_track.py`）：状态机主循环，调用现有 `G1TrackMjSim`/`G1TrackInferFn`
- 复用：`tennis_hit_test.py` 的 `build_sim`/`site_state`/`contact_event` 抽到公共位置（避免复制）

## 6. 风险与对策

| 风险 | 依据 | 对策 |
|---|---|---|
| 无腕部修正 → 命中率天花板 | LATENT 消融（w/o Corr. 正手 96.5→82.4） | 接受；V1 的失误分类数据可作为第二步 RL 的立项依据 |
| 预测误差累积（弹跳后） | 反弹系数随机化后落点发散 | 只在弹跳前拦截（击球高度取来球下降段）；预测输出置信度 |
| 片段初始 reset 与 walk 结束姿态不连续 | play_track 现有 reset 即跳变 | V1 容忍；V3 若劣化明显，考虑片段前接过 ready 姿态过渡（数据层面） |
| 反手/移动数据语义未知 | 四条轨迹未标注 | V2 前置人工标注任务（用 --tennis 交互窗口看叠影） |
| 50g 拍与真拍差异 | #9 节结论（0.3kg 崩） | 本方案全程 50g 拍；真拍留给第二步训练 |

## 7. 与第二步（RL 微调）的衔接

本方案的产出直接服务第二步立项：

- 发射器 + 随机化代码 → RL 训练环境的事件重置逻辑
- 观测噪声模块 → RL 观测接口
- V1 的失误分类 → RL 奖励设计的依据（哪些误差最伤命中率）
- LATENT 开源训练代码（`GalaxyGeneralRobotics/LATENT`）作为训练框架参考
