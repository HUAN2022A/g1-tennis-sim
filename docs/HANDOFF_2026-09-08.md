## 2. 本次完成（2026-09-08）：V3 调试

### 2.1 修掉的 4 个真实 bug（`scripts/tennis_v3_walk_intercept.py`）

1. **WALK 段球没加空气阻力**：`walk_step` 直接 `mj_step`，球按纯抛体飞，而发球（`design_serve_with_drag`）与预测器都假设有阻力 → 拦截点预测整体失真。已给 `walk_step` 加 `apply_drag`（与 `step_with_drag` 一致）。
2. **`start_offset` 方向反了**：原 `(0.4,0)` 让机器人起步在拦截点**前方**，goto 要原地转 180°（最大偏航 0.5 rad/s ≈ 6s，比飞行还久）永远走不到。改 `(-0.4,0)` 从拦截点后方向前走。
3. **重定向太早锁死 offset**：预测未收敛（t_arr≈2s）就锁定拦截偏移，误差 ~0.4m。改为 `redirect_lead=0.90`（t_arr 降到该值以下才重定向），预测外推时域缩短到 ~0.9s。
4. **站桩 hold 时长与标定不一致**：触发与 t_arr 耦合导致 hold 时长可变，挥拍跟踪漂移（标定陷阱）。改为重定向后**固定站桩 `hold_frames` 帧**再挥拍，不与 t_arr 耦合。

另：**步行目标固定为 `onset_root`**（标称拦截点），实际拦截偏移只在重定向瞬间用已收敛预测统一施加——避免早期预测噪声让 nav_target 漂移、慢速步行绕不回来。

### 2.2 在线阻力系数估计（`utils/ball_predict.py` / `utils/ball_obs.py`）

- `fit_ball_state` 从 6 参数 (p0, v0) 扩到 7 参数 (p0, v0, **k**)，Gauss-Newton 在线辨识真实阻力系数，返回 `k_est`。
- `read_fit` 返回 `(pos, vel, k_est)`；V1/V2/V3 的调用点用 `k_est` 传给 `predict_intercept`（此前固定用 `pred_drag_k`）。

### 2.3 关键发现（定性结论）

**长滞空发球是 V3 难的根本原因，不是走路 bug。**

球从 ~1.5m 高抛出、空中滞留 T 秒，回落过拦截点时速度必然是 **g·T/2 ≈ 12 m/s**（V1 短滞空 0.65-0.85s 只有 ~4 m/s），命中窗口被压缩到 ~1 帧（0.02s = 0.24m 垂直误差）。

对照实验（站桩 V1 用同样长滞空 + 随机阻力 + 噪声）：

```
站桩 V1 (flight 2.5-2.9s): HIT 0/20 = 0%，MISS_SWUNG 拍面离球均值 1.035m
```

即交接文档 2026-09-07 归因于「walk→teleport 不稳定」的 ~1m 偏差，**绝大部分是发球时序敏感，而非走路/teleport 问题**。最短飞行时间被「步行到达 ~0.8-1.0s + `redirect_lead` 0.9s（hold 0.6s + 挥拍 0.26s + 补偿）」锁死在 ~1.9s，回落速度 ~9-12 m/s 接近物理下限。
