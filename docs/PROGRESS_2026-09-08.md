## 二、今日进展（09-08）🚀

### 2.1 V3 修通：跟踪误差 1m → 0.006m 🔧
修复 4 个真实 bug：
1. **walk 段球未加空气阻力**——球按纯抛体飞，与发球/预测器的阻力假设不一致，拦截点预测整体失真
2. **`start_offset` 方向反了**——机器人起步在拦截点前方，goto 原地转 180°（约 6s，比飞行还久）永远走不到
3. **重定向过早锁死 offset**——预测未收敛（t_arr≈2s）就锁定拦截偏移，误差 ~0.4m → 改 `redirect_lead=0.90`
4. **站桩 hold 时长与标定不一致**——触发与 t_arr 耦合导致 hold 可变，挥拍跟踪漂移 → 改固定 `hold_frames=30` 帧

### 2.2 关键发现：命中率天花板在发球时序，不在走路 ⚠️
- 长滞空发球回落过拦截点时速度必然为 **g·T/2 ≈ 12 m/s**（V1 短滞空仅 ~4 m/s），命中窗口被压缩到 ~1 帧（0.24m 垂直误差）
- 对照实验：站桩 V1 用同样长滞空发球 **0/20 = 0%**——昨日归因于「walk→teleport 不稳定」的 ~1m 偏差，绝大部分实为发球时序敏感
- 结论：V3 机制已全部跑通，剩余误差是发球时序的物理上限，不是代码缺陷

### 2.3 演示录制与交互仿真 🎥
- 新增离屏录制 `record_tennis_demo.py`（无 GUI 环境逐控制步渲染 mp4），产出 `logs/tennis_demo_v1_racket_v3.mp4`（1280×720 / 50fps，5 连命中；抽帧质检：触球点落在弦床中部）
- 交互仿真：`python -m deploy.play_track --tennis --no-mocap` 弹出 MuJoCo 视窗，数字键控制 walk / 叠影观察（V2 标注用）

### 2.4 V1 回归排查与修复 🔧
- 昨日提交的在线阻力系数估计引入回归：7 参数联合拟合 (p0,v0,k) 在短观测窗下病态，返回的 (pos,vel) 被污染，验收 **50% → 24%**
- 修复：`fit_ball_state` 加 `refine_k` 开关，V1 恢复固定 k 拟合路径（V3 保留在线估计）→ 验收位级复现昨日 **25/50 = 50%**（逐球一致），单测 5/5 PASS

### 2.5 拍面朝向修正（V0 遗留 bug）🎯
- 碰撞代理法向自 V0 起写在拍柄方向（"手镜"构造），球一直是擦拍盘外缘环带命中（HIT site-球距 ~0.15m）
- 4 候选法向（±Y/±Z）实测选定**腕系 Z**（±Y 被证伪为纯框缘擦击）：正面击球 HIT min dist **0.147 → 0.106m**
- 副作用：正面拍面更"诚实"也更挑时序，验收暂时暴露为 38%（FAIL）→ 引出 2.6 的触发修正

### 2.6 V1 触发时序修正：38% → 62% ✅
- τ 仪表确证触发链系统性偏晚 **2 帧**（观测标签语义 1f + 挥拍启动/门限 1f），预测器本身无偏（+0.11f±0.3）
- 新增 `trigger_bias_frames=-2`：验收 **62%（31/50，PASS）**、干净 20 球 **65%（13/20）**、HIT min dist **0.084m**（接近甜点）
- 演示视频已按新基线重录（`logs/tennis_demo_v1_racket_v3.mp4`）

### 2.7 V3 触发诊断：无同款偏晚 ✅
- V3 的 `redirect_lead=45f` 已内建 2f 补偿，τ 实测居中（−0.80f，HIT 球 ≈0）；同款 `trigger_bias_frames` 旋钮各档均有害，**默认 0 维持**
- 完整设置（随机阻力+5mm 噪声）**2/20 = 10%**，隔离（固定阻力+零噪声）**4/8 = 50%**

### 2.8 其他提交 ✅
