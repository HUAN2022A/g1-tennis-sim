# 与 LATENT 论文的同口径对比（SR@2.5m）

一句话结论：在论文的同口径指标（回球落点距目标 ≤ 2.5 m 的比例，SR@2.5）下，本仓库当前回球策略为
**全球 15.6%（156/1000）、过网球 26.3%（136/518）**；LATENT 论文仿真正手为 **96.5%**。
差距约 **6×**，且即使只比"过网球"也约为论文的 1/4；该差距是**结构性**的（动作权限），
不是 reward 调参或几何重定义能闭合的。

> 数据来源与可信度：本文所有"我们"的数字由 1000 球 raw per-ball 数组（`sr_w0..w3.npz` + `sr_merge.txt`）
> 于成文时**重新计算并逐项核对**得到，与探针当时的输出**完全一致**。论文数字来自
> arXiv:2603.12686v1，并与本仓库 `docs/LATENT_PAPER_NOTES.md` §6 交叉核对一致。凡无法核验或为估计值处均已标注。

## 1. 指标口径对照

| 指标 | 精确定义（出处） | 与论文是否可比 |
|---|---|---|
| **论文 SR（仿真，Table 3）** | 回球落点落在**目标点 2.5 m 内**的试验比例（10,000 trials） | ← 这是我们要对齐的口径。我们的 SR@2.5 与之**同义可比** |
| **论文 DE（仿真，Table 3）** | 落点→目标点的**平均距离**（LATENT 仿真 1.3–1.9 m） | 与我们 `land_dist` **同义可比** |
| **论文真机 SR（Table 5）** | **口径被重定义**为"回球落在对手半场任意位置"（20 次人-机对拉） | 与我们的 `over-net` 近似（但更严格：见下），**与 SR@2.5 不同义** |
| **我们的 `hit`** | 挥拍窗口内球拍-球**发生接触**（`rl/tennis_env.py:656,863` `swing_stepped & contact`） | **不可比**：这是**接触率，不是落点精度** |
| **我们的 `over-net`** | 落点 `landing_x > NET_X = 3.0`（`rl/tennis_env.py:897`） | 弱于论文真机口径（论文要求落在**对手半场/场内**，我们只要求过 x=3 的网线，可能出界） |
| **我们的 `land_dist`** | `‖landing_xy − target_landing‖`（`rl/tennis_env.py:893-895`）；target 每局均匀采样 `x∈[4,10], y∈[-4,4]`（`:117-118,729-730`） | 与论文 DE **同义可比** |

**必须强调的口径陷阱**：本仓库"命中率 96.2%"是**拍-球接触率**，完全**不代表**回球能落到目标附近。
论文的 **96.5%** 是"落点在目标 2.5 m 内"的成功率。**"96% vs 96.5%"两个数字的近似纯属巧合、毫无含义**——
两者度量的是两件不同的事。任何把二者并列解读为"我们已达论文水平"的说法都是错的。

## 3. 差距

- **全球 15.6% vs 论文仿真正手 96.5% ⇒ ≈ 6.2×**。
- **过网球 26.3% vs 96.5% ⇒ ≈ 3.7×**，即过网口径下仍只有论文的约 1/4。
- 我们的 **p10 = 2.00 m** 意味着：只有**最好的约 10%**回球能进入论文的典型 DE 区间（仿真 1.3–1.9 m）。
  换言之，论文的"平均水平"约等于我们的"前 10% 水平"。
- 论文自己的**腕部消融**（去掉 wrist correction，正手）仍有 **82.4%**，去掉 LAB 为 **93.1%** ——
  即论文"砍掉一条关键机制"后的退化版，仍是我们的 **≈5.3×**。
- 一个诚实的旁证（非 SR@2.5 口径）：论文**真机**正手 DE = **3.15 m**（Table 5，真机 SR 口径为"落在对手半场"）。
  我们的过网球平均落点距 **3.68 m**、全球 **4.54 m** —— 单看"平均距离"，与论文真机 DE 在同一量级；
  但这**不构成** SR@2.5 的追赶，因为二者口径不同（真机 DE 不要求落在 2.5 m 内）。

## 4. 根因（三条证据）

以下三条来自早前探针（非本次 1000 球重算），此处按其原始结论引用。

### 证据一：腕部可达落点集远小于目标盒，且与目标无关

右腕 3-DOF（`ACTION_R_DIM=3`）的可达落点集实测为 **x ∈ [2.0, 5.34]、y ∈ [−1.75, 1.15]**。
它与目标盒（x∈[4,10]、y∈[−4,4]，面积 48 m²）的**交集**仅 `(5.34−4.0)×(1.15−(−1.75)) = 1.34×2.9 = 3.89 m²`，
即目标盒的 **8.1%**。同时 `corr(landing, target) ≈ 0`（实测 `corr_x = −0.087`、`corr_y = +0.063`）——
落点分布与目标几乎不相关，说明腕残差对"瞄准"基本没有权限。

### 证据二：加入近端手臂 DOF 也不增加落点权限

手臂权限探针（200 球、固定 δ 逐球计 `max|Δland_x|`）：

| 关节 | idx | max\|Δland_x\| | 判定（KILL 阈值 0.3 m） |
|---|---|---|---|
| shoulder_pitch | 22 | 0.071 m | KILL |
| elbow | 25 | 0.266 m | KILL |
| shoulder_roll | 23 | 0.025 m | KILL |
| shoulder_yaw | 24 | 0.974 m | 灰区（命中回归） |
| wrist_roll | 26 | 1.050 m | 已在动作空间内 |

结论：**加大近端手臂 DOF 并不带来落点权限**——闭环冻结跟踪器会抵消约 50% 的指令位移，
手臂姿态对球落点的净影响极小。这直接否定了"扩动作空间就能瞄准"的直觉路径（对应 `RL_STAGE3_PLAN` 方向 A 的判死条件）。

### 证据三：过网奖励已饱和，且未过网球零梯度

`net_z_mean_over ≈ 1.46 m` ⇒ `(1.46 − 0.914)/0.15 = 3.64` ⇒ `tanh(3.64) = 0.9986`，
工作点斜率 `20·sech²(3.64) ≈ 0.055 /m`，仅为峰值 `clear_w/CLEAR_SCALE = 20 /m` 的 **0.275%**。
未过网球走常数回退 `3·tanh(−3) = −2.9852`（`rl/reward.py:120`），**严格零梯度**。
即 reward 在"过网"这件事上已退化为二值位，无法提供"差多远/多准"的学习信号。
（注：`docs/RL_STAGE3_PLAN.md` §2(i) 打印为 0.9985 / 0.057，本文按重算取 0.9986 / 0.055，差异仅在末位。）

## 5. 结论与影响

**差距是结构性的，不是调参问题。** LATENT 用**整身上肢的隐技能策略**学习挥拍本身：
低层 tracker 从一开始就把右腕从职责中移除并施加扰动，高层 planner 直接输出腕修正，隐动作经冻结 decoder
展开为 26 维全身动作——因此"球往哪打"落在**整条手臂链**的控制之下。我们的方案是
**冻结跟踪器回放 + 3-DOF 腕残差**：全身动作几乎不可改，腕部可达落点集只覆盖目标盒的 8.1%，
且与目标无关（`corr ≈ 0`）。在给定动作接口下，**瞄准能力的天花板是硬约束**。

由此：

- **reward 调参/课程/几何重定义都不能闭合该差距**。§4 三条证据分别封死了"腕部权限不足""加近端 DOF 无用""reward 梯度已饱和"三条捷径。
- `RL_STAGE3_PLAN` 方向 A（扩近端 DOF）已被权限探针判死；方向 B（修 reward 梯度）最多让过网率 +1~3 pp；
  方向 C（重定义目标域）是**纯几何**改善、无损真实能力。
- `RL_STAGE3_PLAN` §6 提出的"降低 SWING 段对持拍臂的跟踪刚度"是**目前唯一指向真瓶颈的小杠杆**——
  它试图把"权限"从机制上打开，但相对 LATENT 的"学习挥拍"，仍只是**很小的一步**：它放宽跟踪器的跟随，
  并不能凭空创造"隐技能动作空间 + 腕修正通道"所提供的那部分可控性。
- **诚实的能力边界**：不改变动作空间（学习挥拍 / latent skill），把 SR@2.5 从 ~16% 提到论文 96% 量级
  **不可实现**；可期待的增量是把过网率从 ~52% 向 58–64% 推、把 SR@2.5 提升若干 pp，量级仍在十几到二十几百分比。
  要进入论文量级，必须走"重训移除右腕的 tracker + 腕修正通道 / 学习挥拍"这类动作空间改造（见 `docs/LATENT_VS_REPO_ACTIONSPACE.md`）。

## 6. 复现

**脚本**：`scripts/probe_sr_threshold.py`（位于 worktree `C:/code/hg-wt-26af5b6`，@ commit `26af5b6`）。

**关键约束（否则失败）**：本 ckpt 的动作维是 **3**（`ACTION_R_DIM=3`，右腕 roll/pitch/yaw）。
主工作树 `C:/code/Humanoid-GPT` 的 `ACTION_R_DIM` 已变为 **5**，**无法加载**该 3-DOF ckpt，
`--eval`/探针都会形状不匹配。**必须**在 `26af5b6` worktree 中运行。ckpt `storage/ckpts/rl/residual_clear_aim.pkl`
在服务器 `hgpt-rl` 容器内（本地 `storage/ckpts/rl` 无此文件），故实际 rollout 在服务器执行。

**4-worker 拆分（同一全局 seed 调度，`key = fold_in(PRNGKey(seed), b)`，跨 worker 的并集 = 单进程 rollout）**：

```bash
# worker w = 0..3，各跑 batches {b : b % 4 == w}，并各自 dump npz
python scripts/probe_sr_threshold.py --ckpt storage/ckpts/rl/residual_clear_aim.pkl \
    --n-balls 1000 --num-envs 8 --seed 0 --worker w --workers 4 \
    --dump-npz "$TMP/sr_w{w}.npz"

# 合并 4 份并出报告（即 sr_merge.txt 的来源）
python scripts/probe_sr_threshold.py --merge "$TMP/sr_w0.npz" "$TMP/sr_w1.npz" \
    "$TMP/sr_w2.npz" "$TMP/sr_w3.npz"
```

**从 raw npz 重算（无需 GPU / ckpt）**：每个 npz 存 `d`(float64, per-ball 落点距)、`over`(bool)、`hit`(bool)。
拼接 4 份（256+248+248+248 = 1000）后：
`SR@t = mean(d <= t)`（过网口径为 `mean(d[over] <= t)`），分位数用 `np.percentile`。
本次成文即按此重算，结果与 `sr_merge.txt` 逐项一致。
